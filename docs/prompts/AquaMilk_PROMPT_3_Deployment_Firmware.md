# AGENT PROMPT 3 — Deployment Firmware (`03_deployment/`)

**Read `PROJECT_CONTEXT.md` first (pin map §3, power/pump §4, model §6, gestures §7, connectivity §8, design §9, conventions §11). Reuse `sensors.h/.cpp`. Use the installed Apple design skill for the device-served dashboard.**

## Your task
Write an **Arduino (ESP32)** sketch `03_deployment.ino` — the finished, standalone tester. It runs the trained SVM on-device, shows the verdict on the TFT, serves its own elegant Wi-Fi dashboard, self-flushes, is driven by one touch pad, and supports soft-power sleep.

## Core flow
1. **Boot:** init sensors, load calibration + settings from NVS, mount LittleFS, include `model.h` + `scaler.h` (from the trainer). Start Wi-Fi in **SoftAP** by default (`AquaMilk-XXXX`, §8); if STA creds saved, join and advertise `aquamilk.local` (mDNS). Serve the dashboard (below) + a **WebSocket** for live push. Show idle screen on TFT (logo, "Tap to test", Wi-Fi/SSID).
2. **Test (single tap or dashboard button):** TFT + dashboard show "Reading…"; take a **~3 s averaged** feature reading; apply calibration + `StandardScaler` (from `scaler.h`); run SVM (`model.h` via micromlgen) → class probabilities.
   - If top prob ≥ threshold (default 0.60, from Settings) → verdict = that class; else **Uncertain**.
   - Show verdict big on TFT with the semantic color (§9): green Pure / red Adulterated-type / amber Uncertain, plus confidence and a one-line reason (top contributing sensors). Push the same to the dashboard over WebSocket.
   - Also compute + show the **binary headline** (Pure vs Adulterated).
   - **Auto-flush** (~5 s, per §4) then return to idle. Log the result.
3. **Uncertain:** amber "Uncertain — retest", auto-suggest flush + retry.

## Touch gestures (§7) — implement robust detection on GPIO27 (single TTP223)
- **Single tap** → start test. **Double tap** → flush now. **Long-press ~1.5 s** → open on-screen menu (navigate with taps: Wi-Fi info · Tare · Re-check calibration · Settings; show a gesture cheat-sheet here). **Tap-tap-hold** → **soft power**: display "Sleeping…", then `esp_deep_sleep_start()`; configure **ext0 wake on GPIO27** so a touch wakes it. Keep timing windows generous and debounced.

## Wi-Fi dashboard (device-served, Apple-grade, LEAN)
Serve a single self-contained page (HTML+CSS+JS, **gzipped in PROGMEM or LittleFS**) that mirrors the web app's design language (§9) but lightweight:
- **Verdict card:** big class word, **circular confidence ring** (SVG), semantic color, binary headline, timestamp.
- **Details (expandable):** every live sensor value + which features drove the decision (bar/relative contribution).
- **History:** this-session list (timestamped) **and** the persistent rolling log (last ~200) read from flash; export-to-CSV button (client-side).
- **Settings:** confidence threshold slider, flush duration, Wi-Fi mode (SoftAP/STA + creds), tare, re-check calibration, factory reset.
- **Controls:** "Run test" and "Flush" buttons (mirror the touch pad).
- Live updates via **WebSocket**; graceful reconnect. Works on any phone/laptop browser (it's plain HTTP on the device).

## Persistence & logging
- Settings + calibration in NVS (`Preferences`). **Persistent rolling test log** (last ~200 results: ts, class, confidence, key features) in LittleFS or NVS blob, survives power cycles (§11).

## Requirements / quality bar
- Respect `PUMP_ACTIVE_LOW` (§4) for all pump control; LEDC PWM on GPIO25.
- All analog on ADC1 (Wi-Fi safe, §3). Non-blocking main loop; async web server (`ESPAsyncWebServer` + `AsyncWebSocket`) recommended.
- `model.h`/`scaler.h` are **generated by the trainer** — commit placeholder stubs with a clear `// TODO: replace with trained model` and a matching feature-order contract so the sketch compiles before training.
- Feature order MUST match the trainer exactly: `[ph, tds, turbidity, density, temperature, color_r, color_g, color_b, color_clear]`. Document this contract in a shared `features.h`.
- Header comment: gestures, endpoints, WebSocket messages, feature order.
